# Задача 4. «Мой прогресс» — промт для разработчика

## Зачем

Студенту нужно место, где он видит все активности по предмету (ДЗ, квизы, КР, экзамен, проект), отмечает их сданными, вводит оценку, когда она известна, и сразу видит свой накоп, посчитанный по формуле предмета.

Главный принцип: минимализм. Новых экранов ровно столько, сколько нужно для отметки и оценки.

## Что уже есть в боте (сверено с кодом, не дублировать)

- **Активности уже хранятся** в таблице `deadlines`: `kind` ∈ `hw | quiz | test | exam | milestone`, `title`, `due_date`. Отдельный справочник активностей не заводим: прогресс отмечается прямо по строкам `deadlines`.
- **Список предметов** уже есть: `services/deadlines.get_screen_subjects()` возвращает предметы текущего модуля плюс предметы с будущими дедлайнами. Используем его.
- **Короткие имена и эмодзи типов** тоже есть: `display_name()`, `KIND_BLOCKS` (📝 ДЗ, 🧠 Квизы/КР, 📋 КР, 🎓 Экзамен, 📌 Этапы). Используем их, новые не заводим.
- **Формула хранится только текстом**, например `0.5·ДЗ + 0.2·КР + 0.3·ЭКЗ · автомат (макс. 7), если ДЗ и каждый тест ≥ 6`. По такому тексту посчитать нельзя, поэтому ниже добавляем структурированные веса.
- **Кнопка «📖 Предметы»** в главном меню до сих пор заглушка (`handlers/subjects.py` с выдуманными предметами). Её место отдаём под новую функцию, пятую кнопку в меню не добавляем.
- Экраны выводятся через `ui.show_screen`, переключатели в боте имеют вид `✅ / ☐`.
- Пользователь при выходе не удаляется (`is_verified = False`), поэтому прогресс переживает logout/login.
- **Риск:** `import_deadlines --prune` удаляет дедлайны, которых нет в источнике. После нашей задачи вместе с ними пропадали бы отметки студентов (см. п. 6).

## 1. Главное меню

- Кнопку «📖 Предметы» заменить на «📈 Мой прогресс», callback `progress`.
- Команду `/progress` добавить, `/subjects` оставить её алиасом.
- Заглушку `handlers/subjects.py` удалить.
- Все callback'и новой функции начинаются с `prog_`. Проверено: это пространство имён в `main.py` свободно.

## 2. Данные (миграция)

- Новая таблица `user_progress`:
  - `id`
  - `user_id → users.id ON DELETE CASCADE`
  - `deadline_id → deadlines.id ON DELETE CASCADE`
  - `done_at TIMESTAMP NULL`: отметка «сдано», `NULL` значит не сдано
  - `grade NUMERIC(3,1) NULL`: оценка 0–10, один знак после запятой
  - `updated_at`
  - `UNIQUE (user_id, deadline_id)`
- Если поставлена оценка, `done_at` заполняется автоматически.
- `subjects.grading_weights JSONB NULL`: веса для расчёта, например `{"ДЗ": 0.5, "КР": 0.2, "ЭКЗ": 0.3}`.
- В `Deadline.KINDS` добавить новый тип `project` («Проект»: у RL проект входит в формулу). Нужно проверить, что карточка, рассылка и график его понимают: добавить в `KIND_BLOCKS`, `KIND_IN_DIGEST`, цвет в `deadline_chart`.

## 3. Веса формулы

Ключи весов привязаны к типам дедлайнов:

| Ключ | Что берём |
|---|---|
| `ДЗ` | все `hw` предмета |
| `Квизы` | все `quiz` |
| `КР` | все `test` |
| `ЭКЗ` | `exam` |
| `Проект` | `project` |
| `ДЗ_1`, `ДЗ_2`… | один дедлайн `hw` с `title = "№1"`, `"№2"`… (так задана формула RecSys) |

- Если ключ не распознан или сумма весов отличается от 1.0 больше чем на 0.01, импорт пишет WARNING.
- Особые правила (автомат, `min(ДЗ, 12)`, бонус за активность, правила округления) **не считаем**. Текстовая формула по-прежнему выводится, а под расчётом идёт пометка «без учёта особых правил, см. формулу».
- Источник весов:
  - в `deadlines.json` у предмета появляется поле `"weights": {...}`;
  - во вкладке «Формулы» Google Sheet добавляется колонка «Веса» в формате `ДЗ=0.5; КР=0.2; ЭКЗ=0.3`.

## 4. Расчёт накопа (`services/progress.py`, чистые функции, покрыть тестами)

- Оценка компонента = сумма оценок по его активностям / число активностей в компоненте. Неоценённые активности считаются как 0.
- **Накоп сейчас** = Σ вес × оценка компонента по всем компонентам, кроме `ЭКЗ`.
- **Максимум накопа** = Σ весов без `ЭКЗ` × 10. Выводится как «4.9 из 7.0».
- **Итог** = накоп + вес `ЭКЗ` × оценка за экзамен. Показывается только когда экзамен оценён.
- По каждому компоненту выводится средняя оценка по оценённым активностям и счётчик «оценено N из M».
- Строка вида `№1–4` считается одной активностью с одной оценкой.
- `milestone` (этапы ВКР) в расчёт не входят: им можно только поставить отметку «сдано».
- Если у предмета нет `grading_weights`, расчёт не выводится, пишется «формула не задана», а отметки работают.

## 5. Экраны

1. **«📈 Мой прогресс»** (`progress`). В тексте по строке на предмет: «Продвинутое МО: ✅ 3/7 · накоп 4.9». Ниже кнопки предметов, по одной в строке, и «🏠 Главное меню».
2. **Прогресс по предмету** (`prog_s_<subject_id>`):
   - активности сгруппированы блоками по `KIND_BLOCKS`;
   - строка активности: `☐`, `✅` или `✅ 8.5`, затем название и срок;
   - ниже текстовая формула и расчёт из п. 4;
   - кнопки активностей по две в ряд (`prog_d_<deadline_id>`), внизу «◀️ К предметам» и «🏠 Главное меню».
3. **Нажатие на несданную активность** сразу ставит «сдано» и открывает экран оценки. На экране вопрос «Оценка известна?», клавиатура `4 5 6 7 / 8 9 10 ✏️ Другая` (`prog_g_<deadline_id>_<grade×10>`) и кнопка «Пока нет». После выбора бот возвращает пользователя на экран предмета с пересчитанным накопом.
4. **Нажатие на сданную активность** открывает экран активности: текущая оценка и кнопки «Изменить оценку», «🗑 Убрать оценку», «↩️ Не сдано» (при нём оценка тоже сбрасывается), «◀️ К предмету».
5. **«✏️ Другая»** запускает `ConversationHandler`: пользователь вводит число, допускаются `7,5` и `7.5` в диапазоне 0–10. Если ввод неверный, бот показывает короткую подсказку и ждёт следующий ввод. Выход по `/cancel`.
6. Для `milestone` экран оценки не показывается: кнопка только переключает «сдано» / «не сдано».

Все экраны выводятся через `show_screen` и помещаются в одно сообщение (лимит 4096 символов). `callback_data` не длиннее 64 байт.

## 6. Защита отметок при импорте

- `--prune` **не удаляет** дедлайн, если по нему есть записи в `user_progress`. Вместо удаления выводится WARNING: «есть отметки у N студентов». Удалить такой дедлайн можно только с флагом `--force-prune`.
- В докстринг импорта добавить правило: дедлайн с отметками не переименовывать (у него меняется ключ upsert), а править дату и время.

## 7. Связка с напоминаниями (небольшая правка задачи 1)

- `deadline_digest` пропускает дедлайны, которые этот пользователь уже отметил сданными. Если после фильтра ничего не осталось, пользователь сообщение не получает.

## 8. Приватность

- Отметки и оценки видит только их владелец.
- Скрипты админа (`announce.py`, импорт) оценки не выводят, только количество записей.

## Критерии готовности

- Вместо заглушки «Предметы» в меню стоит «📈 Мой прогресс». Остальные кнопки и callback'и работают как раньше.
- Путь «отметил → поставил оценку → увидел новый накоп» занимает не больше 2 нажатий.
- Тесты на расчёт: ПМО (`0.5·ДЗ + 0.2·КР + 0.3·ЭКЗ`), RecSys (`ДЗ_1`/`ДЗ_2`), предмет без весов, частично оценённый компонент.
- `--prune` не удаляет дедлайны с отметками.
- Сданный дедлайн не приходит в утреннем напоминании этому студенту.
- Тексты и значки взяты из макета дизайнера `ui_progress.md` (задача для дизайнера — `progress_designer.md`).

## Дополнение после макета (`ui_progress.md`)

Макет готов: `docs/ui_progress.md`. Тексты, разметку и подписи кнопок переносить оттуда дословно. При макетировании сверялись с реальными данными (`scripts/deadlines.json`) и кодом, и нашлось несколько мест, где пункты выше нужно уточнить. **Где этот раздел противоречит пунктам выше, верен он.**

### Д1. Служебные строки в `deadlines` (уточняет п. 2)

В данных есть строки, которые активностями не являются:
- жёсткие сроки заведены отдельными строками: `ДЗ №1 жёсткий (−1 балл/сутки после 04.10)`;
- пересдачи: `Пересдача теста №1 (по спискам)`;
- бонусы: `Practice 3 (бонус)`.

Если ничего не сделать, ДЗ №1 появится в прогрессе дважды, а средняя по ДЗ посчитается неправильно. Что сделать:
- `deadlines.progress_role VARCHAR(10) NOT NULL DEFAULT 'item'`, значения:
  - `item` — обычная активность;
  - `bonus` — показывается со словом «бонус», оценку поставить можно, но в накоп и в счётчик «сдано X/Y» она не входит;
  - `hidden` — в прогрессе не показывается.
- В `deadlines.json` у строки появляется необязательное поле `"progress": "bonus" | "hidden"`, в Google Sheet — колонка «Прогресс». Если поле пустое, это `item`.
- В текущем `deadlines.json` проставить:
  - `hidden` всем строкам «… жёсткий …» и «Пересдача …»;
  - `bonus` для `Practice 3 (бонус)`.
- Импорт пишет WARNING, если у `item` в названии есть «жёсткий», «пересдача» или «бонус». Это подсказка, что роль забыли.
- Карточка дедлайнов, рассылка и график `progress_role` **не учитывают**: там эти строки нужны, как и раньше.

### Д2. Ключи весов — коды типов (заменяет таблицу п. 3)

У ПМО в формуле написано «КР», а тесты в данных лежат как `quiz` (тип «КВИЗ/КР»). Если сопоставлять по русским подписям, вес молча потеряется. Поэтому ключи весов — коды типов:

```json
"weights": {"hw": 0.5, "quiz": 0.2, "exam": 0.3}          // ПМО
"weights": {"hw:№1": 0.29, "hw:№2": 0.29, "exam": 0.42}   // RecSys
"weights": {"hw": 0.3, "quiz": 0.3, "project": 0.4}       // RL — без экзамена
```
- Допустимые ключи: `hw | quiz | test | exam | project`. Отдельная активность задаётся как `<kind>:<title>`.
- В Google Sheet в колонке «Веса» тот же формат: `hw=0.5; quiz=0.2; exam=0.3`.
- Подписи компонентов в таблице накопа берутся из `KIND_BLOCKS` (`ДЗ`, `Квизы/КР`, `Экзамен`, `Проект`). Для поэлементных ключей подпись строится как в кнопке: `ДЗ №1`.
- Если ключ `<kind>:<title>` не совпадает ни с одной строкой (у RecSys ещё нет ДЗ №2), это не ошибка импорта. Компонент считается равным 0, в таблице выводится `— · нет в списке`, а его вес входит в максимум.
- Если в формуле нет `exam` (RL), максимум = Σ всех весов × 10, а «Итог» не выводится никогда. Накоп у такого предмета и есть итог.

### Д3. Расчёт: что считать и как показывать (уточняет п. 4)

- В расчёт и в счётчики идут только `item`. `bonus` и `hidden` не входят никуда.
- Таблица накопа: на каждый компонент формулы `средняя по оценённым · оценено N из M`. Сам накоп при этом считается со средней «неоценённое = 0», как в п. 4. Чтобы цифры не выглядели противоречием, в макете есть курсивная пометка.
- Точность вывода: оценки как введены (`8`, `7.5`), средние с одним знаком, накоп и итог с двумя (`2.70`). Внутри считать в `Decimal`, округлять только при выводе.
- Проверка на макете: ПМО, середина модуля → `2.70 из 7.0`; конец модуля → `5.75`, итог `7.85`; RecSys → `2.61 из 5.8`. Эти три кейса и RL без экзамена взять в тесты как есть.

### Д4. Экраны и навигация (уточняет п. 1 и п. 5)

- Главное меню: `[ ⏳ Дедлайны ] [ 📈 Мой прогресс ]` во второй строке. В боте сейчас «⏳», а не «⏰», значки не путать.
- Возврат везде одной кнопкой `◀️ Назад`, как в карточке дедлайнов. Кнопки «🏠 Главное меню» и «◀️ К предметам» из п. 5 не нужны.
  - список предметов → главное меню;
  - экран предмета → список;
  - экраны активности и оценки → экран предмета.
- Список предметов: тот же набор и порядок, что `build_subject_buttons()`, но без «❗» в подписи. Удобно вынести сортировку в общую функцию с флагом `mark_urgent`.
- Подписи кнопок активностей строит одна функция по правилам из макета:
  - «№…» → тип + номер;
  - скобки отрезаются;
  - до 14 символов с «…»;
  - этапы ВКР — по одной в ряд, `дата · название`, до 28 символов.
- На экране выбора оценки добавлена кнопка `↩️ Отменить`: снимает отметку, если нажали по ошибке.
- Экран сданной активности без оценки показывает `✏️ Поставить оценку` и не показывает `🗑 Убрать оценку`.
- Подсказки после нажатий: `query.answer(text)` с текстами из макета (`ДЗ №2: 8`, `ДЗ №2: не сдано`, …).
- После ручного ввода (п. 5 макета) экран предмета открывается с первой строкой `<i>Сохранено: ДЗ №2 — 7.5</i>`. Ответ на текстовое сообщение идёт через `show_screen`, он сам удаляет старый экран.
- Этапы ВКР (`milestone`) по нажатию только переключаются, экран оценки для них не открывается.

### Д5. Callback'и

| Действие | callback_data |
|---|---|
| список | `progress` |
| предмет | `prog_s_<subject_id>` |
| нажатие на активность | `prog_d_<deadline_id>` |
| оценка с клавиатуры | `prog_g_<deadline_id>_<grade×10>` |
| пока нет | `prog_skip_<deadline_id>` |
| отменить / не сдано | `prog_undo_<deadline_id>` |
| убрать оценку | `prog_clr_<deadline_id>` |
| изменить / поставить оценку | `prog_edit_<deadline_id>` |

- Каждый обработчик проверяет, что дедлайн существует и пользователь авторизован. Дедлайн может исчезнуть при импорте с `--force-prune` между нажатиями. В этом случае показать `<i>нет информации</i>` и кнопку `◀️ Назад` к списку.

### Д6. Лимиты

- У ВКР 13 этапов, это 13 кнопок плюс «Назад». Это укладывается в лимит Telegram (100 кнопок), а текст укладывается в 4096 символов.
- Если когда-нибудь у предмета окажется больше 20 активностей, оставить на экране все строки текста, а кнопки показать только для незакрытых и последних 6 сданных. Сейчас такого нет: делать заранее не нужно, достаточно комментария в коде.
