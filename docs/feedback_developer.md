# Задача 6. Обратная связь — промт для разработчика

## Зачем

Студент должен из бота сказать автору спасибо или написать ему: сообщить об ошибке в сроках, предложить идею. Сейчас такого места нет, и обращения приходят в личку. Реальное обращение см. в `feedback_designer.md`: спасибо, идея и две неточности в данных в одном сообщении примерно на 600 символов.

Главный принцип: минимализм. Одна кнопка в меню, один экран, один ввод текста, ответ автора прямо через бот.

## Что сейчас в коде (сверено)

- Главное меню (`commands._build_main_menu_keyboard`): `[📅 Расписание][🔔 Уведомления]` / `[⏳ Дедлайны][📈 Мой прогресс]` / `[🚪 Выйти]`.
- Админской роли в боте нет: объявления отправляются CLI-скриптом `scripts/announce.py`, `ADMIN_IDS` в коде не используется.
- Ввод текста уже сделан через `ConversationHandler` (`custom_period_handler`, `progress_input_handler`) — новый ввод делать по тому же образцу.
- Экраны выводятся через `ui.show_screen`, рядом есть `show_photo_screen`.
- Карточка предмета в дедлайнах: `show_subject_card`, кнопка `◀️ Назад` → `deadlines`.

---

## 1. Данные (миграция)

- `users.thanked_at TIMESTAMP NULL` — студент сказал спасибо (один раз навсегда). Отдельная таблица лайков не нужна.
- `feedback`:
  - `id`
  - `user_id → users.id ON DELETE CASCADE`
  - `text TEXT NOT NULL`
  - `context VARCHAR(100) NULL` — откуда написали, например `Дедлайны · RecSys`
  - `created_at`
  - `admin_message_id BIGINT NULL` — id сообщения в чате автора, по нему находится обращение, когда автор отвечает
  - `answered_at TIMESTAMP NULL`
- `.env`: `FEEDBACK_CHAT_ID` — Telegram id автора (или чата), куда приходят обращения. Если переменная не задана, кнопка «💬 Обратная связь» не показывается, а в лог пишется WARNING на старте.

## 2. Главное меню

- Третья строка: `[ 💬 Обратная связь ] [ 🚪 Выйти ]`, callback `fb`.
- Команда `/feedback`, строка в `/help`.

## 3. Экран «💬 Обратная связь» (`fb`)

- Текст и кнопки берутся из макета (`ui_feedback.md`).
- Кнопка «спасибо» (`fb_thanks`):
  - если `thanked_at` пустой, записать время и показать подсказку из макета; экран перерисовывается с новым числом;
  - если уже заполнен, только подсказка, данные не меняются;
  - число на кнопке = `count(users.thanked_at IS NOT NULL)`; при 0 число не пишется;
  - значок на кнопке зависит от студента: 🤍 — ещё не говорил, ❤️ — уже сказал;
  - автору отправить одну строку с `disable_notification=True`, чтобы не будить: «❤️ Спасибо · Имя (@username) · всего N» (формат — `ui_feedback.md`, п. 7).
- Кнопка «написать» (`fb_write`) запускает ввод из п. 4.
- `◀️ Назад` ведёт в главное меню.

## 4. Ввод обращения (`ConversationHandler`)

- Входы:
  - `fb_write` — из экрана обратной связи, `context = NULL`;
  - `fb_write_s_<subject_id>` — из карточки предмета (п. 6), `context = "Дедлайны · <short_name>"`;
  - `fb_write_r_<feedback_id>` — кнопка «✏️ Ответить» под ответом автора (п. 5), `context = "ответ на №<feedback_id>"`. Чужой `feedback_id` (не этого студента) — игнорировать.
- Заголовок экрана ввода и ошибок зависит от входа: `Сообщение автору` / `Неточность: <short_name>` / `Ответ на обращение №N`.
- На экране ввода студента предупреждаем, что автор увидит **имя и почту** (автору уходит email из `users`).
- Состояние ожидания текста:
  - принимается текст длиной от 1 до 1000 символов (`FEEDBACK_MAX_LEN = 1000`), лишние пробелы по краям обрезаются;
  - если текст длиннее, показать ошибку из макета с фактической длиной и ждать дальше;
  - на фото, стикер, голосовое и прочее не-текстовое — ошибка «только текст», ждать дальше. Если у фото есть подпись, её не берём, чтобы не терять картинку молча;
  - `/cancel` возвращает туда, откуда пришли: экран обратной связи, карточка предмета или (для «Ответить») главное меню.
  - Ошибки ввода заменяют экран ввода (`show_screen`), сообщение студента остаётся в чате.
- Лимит: **5 обращений в сутки** на студента, считается по `feedback.created_at` за последние 24 часа. При превышении ввод сразу показывает ошибку из макета и ничего не ждёт. В ошибке — время, когда можно снова: `created_at` самого старого из 5 обращений + 24 ч, МСК, в формате `после 18:40` или `завтра после 18:40`.
- После отправки:
  1. сохранить запись в `feedback`;
  2. отправить автору сообщение в `FEEDBACK_CHAT_ID` (формат из макета, п. 7): номер, имя и @username, email из `users`, контекст, текст в `<blockquote>`. Текст студента экранировать (`html.escape`);
  3. записать `admin_message_id`;
  4. студенту показать экран «Отправлено» из макета: кнопка `🏠 Главное меню`, а при входе из карточки предмета ещё `◀️ К предмету` (→ `deadlines_subj_<subject_id>`).
- Если автору отправить не удалось, запись всё равно остаётся в БД, в лог пишется ERROR, студент видит «Отправлено». Обращение не теряется, его можно найти в таблице.

## 5. Ответ автора

- `MessageHandler`: `filters.Chat(FEEDBACK_CHAT_ID) & filters.REPLY & filters.TEXT`.
- По `reply_to_message.message_id` найти `feedback.admin_message_id`.
  - Не нашлось (автор ответил не на обращение) — молча игнорировать.
  - Нашлось — отправить студенту сообщение «Ответ автора» из макета: дата и первые 50 символов обращения (обрезка по слову, без переносов), ответ в `<blockquote>`, кнопка «✏️ Ответить» (`fb_write_r_<feedback_id>`). Записать `answered_at`, автору поставить реакцию 👍 на его ответ (`set_message_reaction`). Если реакции недоступны, коротко ответить «✓ доставлено».
  - Студент заблокировал бота — ответить автору «⚠️ Не доставлено: студент заблокировал бота».
- Ответ студенту фоновый, как дайджест: он остаётся в чате и идёт мимо `show_screen`.
- На один `feedback` можно отвечать несколько раз, каждый ответ доставляется. `answered_at` хранит время первого ответа.

## 6. Кнопка в карточке предмета

- В `show_subject_card` над `◀️ Назад` добавить кнопку «✏️ Неточность?» → `fb_write_s_<subject_id>`.
- В карточке «Моего прогресса» эту кнопку **не** добавлять: там отметки студента, а не данные бота.

## 7. Callback'и

| Действие | callback_data |
|---|---|
| экран | `fb` |
| спасибо | `fb_thanks` |
| написать | `fb_write` |
| написать из карточки | `fb_write_s_<subject_id>` |
| ответить на ответ автора | `fb_write_r_<feedback_id>` |

Префикс `fb` в `main.py` свободен. Шаблоны нужно задать строго (`^fb$`, `^fb_thanks$` …), чтобы они не пересекались друг с другом.

## 8. Приватность

- Текст обращения видит только автор. Скрипты (`announce.py` и др.) тексты обращений не выводят.
- О том, что автор увидит имя студента, сказано на экране ввода (по макету).

---

## Критерии готовности

- Сообщение из примера (около 600 символов, эмодзи, переносы строк) доходит до автора целиком и без искажений, вместе с именем и контекстом.
- 1001 символ отклоняется с понятной ошибкой, фото отклоняется, шестое обращение за сутки отклоняется.
- Вход из карточки RecSys: у автора контекст `Дедлайны · RecSys`.
- Автор отвечает reply'ем, студент получает ответ, у автора видно подтверждение доставки.
- Второе «спасибо» от того же студента не меняет счётчик; кнопка у него ❤️, у остальных 🤍.
- Студент отвечает на ответ автора кнопкой «✏️ Ответить»: у автора приходит новое обращение с «Откуда: ответ на №N».
- Шестое обращение за сутки показывает время, когда можно снова.
- Если `FEEDBACK_CHAT_ID` не задан, кнопки нет и бот не падает.
- Тексты взяты из `ui_feedback.md` (задача дизайнеру — `feedback_designer.md`).
