# Задача 5. Маголего — свой набор предметов у каждого студента

Промт для разработчика. Дизайнер не нужен: тексты экранов даны ниже, стиль тот же, что в `ui_deadlines.md` и `ui_progress.md`.

## Зачем

Расписание у всех студентов общее, кроме маголего. На маголего каждый записывается сам: кто-то ходит на одно, кто-то на два, кто-то ни на одно. Сейчас бот этого не различает. Студент выбирает одну «группу» (`Общий поток` / `Маголего` / `все потоки`), а дедлайны, график и прогресс показывают все предметы подряд.

Как должно быть: студент сам отмечает «Общие предметы» и любые маголего в любом сочетании. Уведомления, расписание, дедлайны, график и прогресс показывают только отмеченное.

## Что сейчас в коде (сверено, учитывать)

- Маголего — это поток `Маголего` в `streams`. Импорт расписания кладёт туда строки с пометкой «(Маголего)». В 5 модуле это RecSys, Обучение с подкреплением, DevOps-2, Алгоритмы и СД. Всё остальное идёт в `Общий поток` (`scripts/import_schedule.py`, `DEFAULT_STREAM`).
- Пользователь выбирает ровно один поток: `users.stream_id`, меню «👥 Группа: …» → `notify_setup` / `notify_stream_<id>`. Специальный поток `все потоки` означает «без фильтра» (`scheduler.ALL_STREAMS_NAME`).
- `scheduler.daily_digest` и планирование напоминаний отбирают пользователей с `User.stream_id != None` и фильтруют по `_stream_filter()`.
- Переключатели «Расписание на день» и «Напоминание за 15 мин» требуют выбранную группу (`needs_group` в `TOGGLES`).
- Дедлайны (`get_screen_subjects`), график (`show_deadline_chart` берёт **все** дедлайны), рассылка дедлайнов (`get_digest_deadlines`) и прогресс (`handlers/progress.py`) о потоках вообще не знают.
- В разделе «📅 Расписание» есть свой выбор потока: `schedule_choose_stream` → `stream_<id>`.
- Кэш картинки графика (`deadline_chart.cache_key`) считается по набору дедлайнов в окне. Если набор фильтруется, ключ сам станет разным, отдельно трогать кэш не нужно.
- `replan_reminders_for_user()` уже есть, его можно переиспользовать.

## Решение

Маголего — это свойство **предмета**, а не потока. Выбор студента — это набор: «общие вкл/выкл» плюс список его маголего. Вся фильтрация идёт через **одну** функцию, ни один раздел не фильтрует по-своему.

Правило видимости предмета:
- предмет-маголего виден, если студент его отметил;
- любой другой предмет (включая ВКР, «Семинар наставника», встречи) виден, если включены «Общие предметы».

---

## 1. Данные (одна миграция)

- `subjects.is_elective BOOL NOT NULL DEFAULT false` — предмет является маголего.
- `users.common_enabled BOOL NOT NULL DEFAULT true` — флаг «Общие предметы».
- Таблица `user_electives`: `user_id → users.id ON DELETE CASCADE`, `subject_id → subjects.id ON DELETE CASCADE`, `PRIMARY KEY (user_id, subject_id)`.
- Заполнение при миграции:
  - `is_elective = true` для предметов, у которых есть строки `schedule` в потоке `Маголего`;
  - всем пользователям `common_enabled = true`, `user_electives` оставить пустой. Так решено: после запуска студенты получат объявление и выберут маголего сами (п. 9).
- `users.stream_id` и таблицу `streams` **не удалять**. Поток остаётся у строк расписания, а `users.stream_id` перестаёт читаться кодом. Колонку можно удалить отдельной миграцией через модуль, когда всё устоится.

## 2. Импорт

- `import_schedule.py`: если у строки поток `Маголего` (константа `ELECTIVE_STREAM`), предмету ставится `is_elective = true`. Если один и тот же предмет встретился и в общем потоке, и в маголего, нужен WARNING: это ошибка в таблице.
- `import_deadlines.py`: у предмета в `deadlines.json` появляется необязательное поле `"elective": true`. Оно нужно для маголего, которого ещё нет в расписании. Сбрасывать `is_elective` в `false` импорт не должен.

## 3. Одна функция фильтра (`bot/services/selection.py`)

```python
@dataclass(frozen=True)
class Selection:
    common: bool
    elective_ids: frozenset[int]

def get_selection(db, user) -> Selection
def is_visible(subject, sel: Selection) -> bool
def subject_filter(sel: Selection)            # SQLAlchemy-условие для запросов по Schedule / Deadline
def get_available_electives(db, today) -> list[Subject]
```
- `subject_filter` → `or_(and_(Subject.is_elective.is_(False), literal(sel.common)), Subject.id.in_(sel.elective_ids))`.
- `get_available_electives` возвращает маголего, у которых есть занятия в текущем модуле или будущие дедлайны (та же логика, что в `get_screen_subjects`). Маголего прошлых модулей в выборе не показываются, но отметки на них не удаляются.
- Неавторизованному пользователю (если какой-то раздел ему доступен) показывается всё, без фильтра.
- Покрыть тестами: все четыре сочетания «общие вкл/выкл × маголего есть/нет», маголего прошлого модуля.

## 4. Экран «📚 Мои предметы»

Открывается из меню уведомлений и по кнопке из объявления. Это множественный выбор: нажатие переключает пункт и сразу перерисовывает экран.

```html
📚 <b>Мои предметы</b>
Уведомления, расписание, дедлайны, график и прогресс — только по отмеченным.
Маголего отметьте те, на которые записаны.
```
```
[ ✅ Общие предметы ]
[ ☐ RecSys ]
[ ☐ Обучение с подкреплением ]
[ ☐ DevOps-2 ]
[ ☐ Алгоритмы и СД ]
[ ◀️ Назад ]
```
- Маголего — по одной кнопке в ряду, короткое имя (`display_name`), сортировка по алфавиту.
- Подсказка после нажатия: `RecSys: вкл` / `RecSys: выкл`, `Общие предметы: выкл`.
- Если доступных маголего нет, под «Общими предметами» выводится строка `<i>маголего в этом модуле нет</i>`.
- Снять можно всё. Тогда бот ничего не присылает, а разделы показывают пустое состояние (п. 6).
- `◀️ Назад` возвращает туда, откуда пришли: в меню уведомлений. Если экран открыт из объявления, назад ведёт в главное меню.
- После любого изменения вызывается `replan_reminders_for_user()`, чтобы напоминания на сегодня пересобрались под новый выбор.
- Callback'и: экран `mysubj`, общие `mysubj_common`, маголего `mysubj_el_<subject_id>`. Префикс `mysubj_` в `main.py` свободен.

## 5. Меню «🔔 Уведомления»

- Кнопку «👥 Группа: …» заменить на «📚 Мои предметы», она ведёт на экран из п. 4.
- Обработчики `notify_setup` / `notify_stream_<id>` и `_show_group_picker` удалить.
- В `TOGGLES` убрать `needs_group`: группы больше нет, переключатели включаются сразу.
- Строка статуса:
  ```html
  🔔 <b>Уведомления</b>
  Включено 3 из 4
  Предметы: общие + RecSys, DevOps-2
  ```
  - Без маголего: `Предметы: общие`.
  - Без общих: `Предметы: RecSys`.
  - Ничего не отмечено: `Предметы не выбраны`.
  - Если маголего больше двух: `общие + 3 маголего`.
  - Строку `Группа не выбрана` удалить.

## 6. Что меняется в разделах

Везде используется `selection.py`, своих условий в разделах нет.

| Раздел | Где | Что сделать |
|---|---|---|
| Расписание на день, 10:00 | `scheduler.daily_digest` | убрать `User.stream_id != None` и `_stream_filter`; занятия фильтровать по `subject_filter` |
| Напоминание за 15 мин | планирование напоминаний в `scheduler` | то же самое. Дополнительно в `_send_reminder` перед отправкой проверять `is_visible` по свежему выбору: студент мог снять предмет после 10:00 |
| Дедлайны за 4, 2, 1 дн | `deadline_digest` | дедлайны каждого пользователя фильтровать по выбору (рядом с `without_done`) |
| ⏳ Дедлайны | `show_deadlines` | `get_screen_subjects` → только видимые предметы |
| 📊 График | `show_deadline_chart` | дедлайны фильтровать **до** `split_items`, тогда и картинка, и подпись «Позже: …» будут только по своим предметам |
| 📈 Мой прогресс | `handlers/progress.py` | список предметов — только видимые. Отметки по снятым маголего не удалять: при повторном выборе они вернутся |
| 📅 Расписание (сегодня / завтра / неделя / месяц / дата) | `handlers/schedule.py`, `utils/database.get_schedule_*` | фильтровать по выбору. Свой выбор потока (`schedule_choose_stream`, `stream_<id>`) удалить. Формат строк занятия не менять |
| 📣 Объявления | — | без изменений, приходят всем с `news_enabled` |

Пустые состояния:
- В «Дедлайнах» и «Моём прогрессе», если не выбрано ни одного предмета: `<i>предметы не выбраны</i>` и кнопка `[ 📚 Мои предметы ]` над `◀️ Назад`.
- Если общие выбраны, а маголего нет, но доступные маголего существуют: внизу списка добавить кнопку `[ 📚 Выбрать маголего ]`, которая ведёт на тот же экран. Когда хотя бы одно маголего выбрано, эта кнопка пропадает.
- В расписании день без занятий по выбранным предметам показывается так же, как сейчас пустой день.

## 7. Карточки по прямой ссылке

- Если студент открыл карточку предмета или прогресса по старой кнопке, а предмет уже снят из выбора, карточку всё равно показываем. Это безопасно и проще, чем проверять. Фильтр работает только на списках и рассылках.

## 8. Объявления: кнопка «Мои предметы»

- В `scripts/announce.py` в `BUTTONS` добавить `mysubj: "📚 Мои предметы"`.
- В `open_section` (`handlers/deadlines.py`) добавить ветку `open_mysubj`. Шаблон `^open_(…)$` в `main.py` расширить.

## 9. Запуск

1. Выкатить миграцию и код.
2. Сразу после этого разослать объявление:
   ```
   python -m scripts.announce --button mysubj
   ```
   Текст:
   ```html
   📣 <b>Новое в боте</b>

   Теперь бот знает, на какие маголего вы записаны. Отметьте свои — и уведомления, расписание, дедлайны и прогресс будут только по ним.
   ```
   `[ 📚 Мои предметы ]`
3. До того как студент отметит маголего, он видит только общие предметы. Это ожидаемо, и именно поэтому объявление уходит сразу.

## Критерии готовности

- Выбор «общие + RecSys»:
  - в дайджесте, напоминаниях, расписании, дедлайнах, на графике и в прогрессе есть общие предметы и RecSys;
  - DevOps-2, RL и Алгоритмов нигде нет;
  - рассылка «за 4, 2, 1 дн» не присылает дедлайны RL.
- Выбор «только RecSys» (общие сняты): нигде нет ВКР и общих предметов.
- Ничего не выбрано: бот ничего не присылает, кроме объявлений; в разделах показывается пустое состояние с кнопкой «📚 Мои предметы».
- Снял предмет в 12:00 → напоминание за 15 минут по нему уже не приходит.
- Прогресс по снятому маголего не теряется и возвращается после повторного выбора.
- Миграция откатывается без потери данных; `users.stream_id` после отката на месте.
- В коде не осталось чтения `users.stream_id`, `_stream_filter`, `ALL_STREAMS_NAME`, `notify_setup`, `schedule_choose_stream`.
- Тесты `selection.py` из п. 3 проходят.
