# Задача 10. Выбор модуля — промт для разработчика

## Зачем

Сейчас модуль определяется только по дате. Когда начнётся 6 модуль, из бота пропадёт весь 5-й: дедлайны, «Мой прогресс» с оценками и накопом, маголего. При этом оценки за экзамены 5 модуля приходят уже в ноябре. Нужна кнопка в главном меню: выбрал модуль, и всё переключилось на него. Уведомления при этом всегда работают по реальным датам.

Тексты экранов — из макета `ui_module.md` (задача дизайнеру — `module_switch_designer.md`).

## Что сейчас в коде (сверено)

- `modules(id, name, start_date, end_date)` загружаются из `deadlines.json` → `"modules"` (`import_deadlines.import_modules`). Сейчас там один «5 модуль» 05.09–01.11.
- `services/deadlines.get_current_module(db, today)` — модуль, в который попадает `today`, иначе `None`.
- `get_module_subjects(db, module)` — предметы по расписанию в датах модуля (без «Встреч»).
- `get_screen_subjects(db, today)` — предметы текущего модуля плюс всё, где есть будущие дедлайны. Используется в `handlers/deadlines.py` и `handlers/progress.py`.
- `selection.get_available_electives(db, today)` — маголего текущего модуля плюс маголего с будущими дедлайнами. Используется в «📚 Моих предметах», дедлайнах и прогрессе.
- Расписание (`handlers/schedule.py`): Сегодня, Завтра, Эта неделя, Следующая неделя, Месяц, Указать период. Всё считается от `today`, фильтр по «Моим предметам» уже есть.
- Главное меню: `commands._build_main_menu_keyboard`.

## Решение

Студент выбирает, какой модуль **смотреть**. Это отдельное понятие от текущего модуля. Вводится одна функция `get_view_module(db, user, today)`, и все экранные разделы берут модуль только из неё. Рассылки и напоминания её **не используют**.

---

## 1. Данные (миграция)

- `users.view_module_id → modules.id ON DELETE SET NULL, NULL` — выбранный модуль. `NULL` означает «текущий».
- `users.view_module_base_id → modules.id ON DELETE SET NULL, NULL` — какой модуль был текущим в момент выбора. Нужен для автосброса (п. 2).

## 2. Какой модуль текущий и какой смотрим (`services/modules.py`)

```python
def get_current_module(db, today) -> Module | None
def get_view_module(db, user, today) -> Module | None
def module_status(module, today) -> Literal['current', 'archive', 'upcoming']
def list_modules(db) -> list[Module]          # по start_date
```
- **Текущий модуль:** тот, куда попадает `today`. Если таких нет (каникулы между модулями) — ближайший будущий. Если и будущих нет — последний прошедший. `get_current_module` перенести сюда, старое место оставить реэкспортом.
- **Смотримый модуль:** `user.view_module_id`, если он задан **и** `user.view_module_base_id` совпадает с id текущего модуля. Иначе — текущий модуль.
  - Так работает автосброс: начался новый модуль, база не совпала, и студент снова видит текущий. В БД ничего чистить не нужно, при следующем выборе поля перезапишутся.
- Для пользователя без выбора (`NULL`) — текущий модуль.

## 3. Какие данные относятся к модулю

- **Предметы модуля** `M`:
  - предметы с занятиями в расписании в датах `M` (`get_module_subjects`, как сейчас);
  - плюс предметы, у которых есть дедлайны с `due_date` в датах `M`;
  - если `M` текущий, плюс предметы с будущими дедлайнами (ВКР и т. п.), как сейчас делает `get_screen_subjects`.
- Сигнатуры `get_screen_subjects(db, today)` и `get_available_electives(db, today)` заменить на `(db, module, today)`. Внутри они используют правило выше, а вызывающий код передаёт `get_view_module(...)`.
- **Дедлайны в карточке предмета:** все дедлайны предмета, как сейчас, без фильтра по датам модуля. У сквозных курсов дедлайны из двух модулей видны вместе — это нормально, у них общая формула.
- **Даты модуля** должны покрывать сессию (`end_date` = последний день экзаменов).

## 4. Главное меню

- Первой строкой, на всю ширину, кнопка модуля (`module`): `🗂 <name> · текущий|архив|скоро` — статус **смотримого** модуля.
- Значок 🗂 и слова статусов — константы в одном месте (`services/modules.py`): они же в плашке, на экране выбора и в подсказках.
- Если `len(list_modules) < 2`, кнопки нет.

## 5. Экран выбора модуля (`module`)

- Текст: пояснение и список модулей с датами (`5 модуль · 05.09 – 01.11`). Кнопки всех модулей по `start_date`: `<name> · <статус>`, у открытого — `✅ ` впереди; callback `module_set_<id>`. Даты на кнопки не выносить — не влезут в 28 символов.
- Выбор:
  - если выбран текущий модуль, записать `view_module_id = NULL`, `view_module_base_id = NULL`;
  - иначе `view_module_id = id`, `view_module_base_id = id текущего`;
  - затем подсказка из макета и возврат в главное меню (обновлённая подпись видна сразу).
- Повторное нажатие на уже выбранный модуль — только подсказка.
- `◀️ Назад` ведёт в главное меню.

## 6. Что переключается

| Раздел | Что сделать |
|---|---|
| ⏳ Дедлайны — список | предметы `get_screen_subjects(db, view_module, today)`. Если модуль нетекущий, первой строкой плашка из макета, кнопки «📊 Все на графике» нет |
| ⏳ Дедлайны — карточка | без изменений (сданное и прошедшее уже вычеркивается); плашка не нужна, достаточно списка |
| 📊 График | только в текущем модуле. Прямой callback `deadlines_chart` при нетекущем модуле открывает список дедлайнов |
| 📈 Мой прогресс — список | предметы смотримого модуля, плашка как в дедлайнах, порядок в нетекущем модуле — как у дедлайнов (алфавит, ВКР последней). Отметки и оценки работают в любом модуле |
| 📚 Мои предметы | список маголего — `get_available_electives(db, view_module, today)`, плашка. Отметки маголего общие (по предмету), не по модулю |
| 📅 Расписание | см. п. 7 |
| 🔔 Уведомления, дайджест, напоминания, рассылка дедлайнов, объявления | **не меняются**, `get_view_module` в них не вызывать |

- Плашку собрать в одной функции `module_banner(view_module, today) -> str | None` и подставлять первой строкой: `🗂 Открыт <b>5 модуль</b> · архив`. Для текущего модуля она возвращает `None`.
- На каждом экране с плашкой (списки дедлайнов и прогресса, «Мои предметы», экран и недели расписания) над `◀️ Назад` / `🏠 Главное меню` — кнопка `🗂 Вернуться в <текущий модуль>` (`module_now_<section>`, section ∈ `deadlines | progress | mysubj | schedule`). Она сбрасывает выбор на текущий (как `module_set_<current_id>`), показывает подсказку и перерисовывает **тот же раздел**, а не главное меню.
- Дедлайны в нетекущем модуле: подсказка `Выберите предмет` (без «· ❗ — меньше 2 дней»), «❗» на кнопках не ставить даже при будущем сроке у сквозного курса, сортировка по `display_name` (сначала кириллица, потом латиница), ВКР последней. В `build_subject_buttons` нужен флаг «без срочности».
- `deadlines_chart` в нетекущем модуле: подсказка `График — только в текущем модуле` и список дедлайнов.

## 7. Расписание в нетекущем модуле

- Экран `schedule`: если смотримый модуль текущий, всё как сейчас. Иначе — плашка, строка `5 модуль · 05.09 – 01.11 · 9 недель`, кнопки «📅 По неделям», «🗓 Указать период», «🗂 Вернуться в …», «◀️ Назад». «Сегодня», «Завтра», «Эта/следующая неделя» и «Месяц» не показываются.
- «📅 По неделям» → `schedule_mw_<module_id>_<n>`, где `n` — неделя модуля, ближайшая к сегодня: в архиве последняя, в будущем модуле первая.
- В модуле нет ни одного занятия — вместо кнопок периода `<i>нет информации</i>`, остаются «🗂 Вернуться в …» и «◀️ Назад».
- Новые экраны расписания — в `parse_mode=HTML` (старые экраны расписания в Markdown, их не трогаем). Строка занятия короткая: `18:10 RecSys · лекция` (время, `display_name`, тип строчными), дни — `<b>пн 21.09</b>`, дни без занятий пропускаются. Без преподавателя, потока и ссылки.
- Неделя `n` модуля: с понедельника недели, в которую попадает `start_date`, плюс `7·(n−1)` дней; всего недель столько, чтобы покрыть `end_date`. Занятия недели — через существующее форматирование недели с фильтром по «Моим предметам».
- Заголовок недели `📅 <b>Неделя n из N</b> · 21.09 – 27.09`. Навигация одной строкой: `[ ◀️ Неделя n−1 ] [ Неделя n+1 ▶️ ]` (`schedule_mw_<module_id>_<n±1>`), на крайних неделях кнопки в ту сторону нет. Ниже «📅 К выбору периода» и «🏠 Главное меню», как у остальных экранов расписания.
- Пустая неделя — `<i>занятий нет</i>` (не «нет информации»: расписание есть, неделя пустая).
- `module_id` в callback нужен, чтобы кнопка недели работала, даже если модуль переключили в другом окне.

## 8. Импорт

- `import_deadlines.import_modules`: WARNING, если даты модулей пересекаются или `start_date > end_date`.
- Чтобы появился 6 модуль, нужно:
  1. добавить в `deadlines.json` → `"modules"` строку `{"name": "6 модуль", "start": "…", "end": "…"}`; даты пока неизвестны, `end` — последний день сессии;
  2. загрузить расписание 6 модуля (`import_schedule.py`, новый лист);
  3. добавить предметы, формулы и дедлайны 6 модуля в `deadlines.json`.

## 9. Callback'и

| Действие | callback_data |
|---|---|
| экран выбора | `module` |
| выбрать | `module_set_<id>` |
| неделя модуля | `schedule_mw_<module_id>_<n>` |
| вернуться в текущий модуль из раздела | `module_now_<deadlines\|progress\|mysubj\|schedule>` |

Префиксы `module` и `schedule_mw_` в `main.py` свободны. Шаблон `^module$` не должен перехватывать `module_set_…` и `module_now_…`.

## Критерии готовности

- Пока в базе один модуль, кнопки в меню нет и всё работает как раньше.
- 05.11 (идёт 6 модуль) студент выбирает 5:
  - в меню `… 5 · архив`;
  - «Дедлайны», «Мой прогресс», «Мои предметы» показывают 5 модуль с плашкой;
  - графика нет;
  - в прогрессе можно поставить оценку за экзамен ПМО, накоп пересчитывается.
- В том же состоянии утренние уведомления приходят по предметам и срокам 6 модуля.
- Расписание 5 модуля листается неделями (9 недель: 31.08 – 01.11), на первой неделе нет `◀️`, на последней нет `▶️`; «По неделям» в архиве открывает 9-ю неделю.
- «🗂 Вернуться в 6 модуль» на экране дедлайнов 5 модуля открывает дедлайны 6 модуля без плашки, с графиком и «❗».
- В 5 модуле на кнопках дедлайнов нет «❗», даже у «Глубинного обучения» с будущим сроком.
- Студент выбрал 5 модуль, затем начался 7: у него снова текущий (7), подпись меню обновилась без его действий.
- Каникулы между модулями: текущим считается ближайший будущий модуль.
- Тесты `services/modules.py`: текущий / каникулы / после последнего модуля; автосброс; правило «предметы модуля» с ВКР и с маголего.
