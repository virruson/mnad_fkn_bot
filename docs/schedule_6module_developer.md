# Загрузка расписания 6 модуля — промт для разработчика

## Контекст

Telegram-бот `mnad_fkn_bot`. Программа выложила обновлённую вкладку «6 модуль (предварительно)» (02.11 – 12.12, дальше сессия). Расписание из неё уже разобрано в `scripts/schedule_6module_parsed.jsonl`. Нужно проверить файл и загрузить его в БД через `scripts/import_schedule.py`.

Файл лежит в репозитории, коммитить его тоже нужно. Код бота менять не требуется, кроме одной правки парсера (см. ниже).

## Что изменилось по сравнению с ранее загруженной версией 6 модуля

Было 40 занятий, стало 41. Ключ занятия (дата + время + поток + предмет) нигде не поменялся, ни одно занятие не исчезло и не перенеслось.

1. **Новое занятие:** 02.11, 18:10–19:30, «Встреча по ВКР» (Руслан Каюмов, УО). Тип занятия — «Встреча».
2. **Ссылки на встречи обновились у всех 40 прежних занятий.** Раньше у ИИ-агентов и ML-lifecycle ссылок не было вовсе, у «Глубинного обучения» была `hse.mts-link.ru/…/24328775031`, у семинара наставника `…/25100071965`. Теперь везде ссылки `my.mts-link.ru/j/176703799/…`. Всего 5 разных ссылок.
3. Преподаватели, время и типы занятий у прежних 40 записей не поменялись.

Ссылка в таблице одна на ячейку. Если в ячейке два занятия (например, 02.11 «Встреча по ВКР» и «Разработка ИИ-агентов», 12.11 семинар наставника и ИИ-агенты), у них будет одна и та же ссылка. Это не ошибка парсера, так заполнена таблица.

## Что уже сделано

- `scripts/schedule_6module_parsed.jsonl` — пересобран из xlsx командой:
  ```
  python scripts/parse_schedule.py <расписание.xlsx> --sheet "6 модуль (предварительно)" \
      --links-from scripts/schedule_5module_parsed.jsonl --links-from scripts/schedule_parsed.jsonl \
      --out scripts/schedule_6module_parsed.jsonl
  ```
- `scripts/parse_schedule.py` — одна правка в `parse_block`: если название начинается с «Встреча», тип занятия по умолчанию «Встреча», а не «Семинар». Без неё «Встреча по ВКР» получила бы тип «Семинар» и стала бы отдельным предметом в «Дедлайнах» и «Прогрессе» (`NOT_A_SUBJECT = ('Встреча',)` в `services/deadlines.py` работает по типу занятия). В файле 5 модуля тип «Встреча» ставился руками.

## Что сделать

1. Проверить diff двух файлов в git: `scripts/schedule_6module_parsed.jsonl` и `scripts/parse_schedule.py`.
2. Прогнать сухой импорт локально:
   ```
   python -m scripts.import_schedule scripts/schedule_6module_parsed.jsonl --dry-run --review-out review6.txt
   ```
   Ожидаемо, если прошлая версия 6 модуля уже была загружена: прочитано 41, создано 1, обновлено 40, пропущено 0, для ручной проверки 0, предупреждений нет. Если прошлую версию в БД не загружали, будет создано 41, обновлено 0.
3. Закоммитить, выкатить `scripts/deploy.sh`, затем импорт на сервере (deploy.sh расписание не импортирует):
   ```
   docker-compose exec -T bot python -m scripts.import_schedule scripts/schedule_6module_parsed.jsonl
   ```
4. Если в конце импорта выведется «Новые предметы: …», передать список администратору — их стоит объявить через `/announce`. Скрипт сам ничего не рассылает.

Импорт ничего не удаляет из БД. В этот раз удалять нечего: ни одно занятие не пропало.

## На что обратить внимание

- **Сессия.** В таблице 21.12 – 31.12 помечены «Сессия» без дат и времени экзаменов, 14.12 – 20.12 занятий нет. Парсер такие записи пропускает, так и должно быть. Модуль в `deadlines.json` задан как 02.11 – 31.12, поэтому недели 14–20.12 и сессия в «По неделям» покажут «занятий нет». Когда появятся экзамены, нужно будет заново прогнать парсер (шаги те же) и импорт.
- **Маголего.** В файле на 6 модуль маголего нет, потоки в этом семестре единые, все занятия идут в «Общий поток». Вкладка «МагоЛего» в файле содержит только 1 и 3 модуль.
- **Название вкладки** временное («предварительно»). Если программа её переименует, меняется только значение `--sheet`.
- Этот промт про расписание. Предметы, формулы и дедлайны 6 модуля в `deadlines.json` — отдельная задача.

- В БД 41 занятие 6 модуля, у всех есть ссылка на встречу.
