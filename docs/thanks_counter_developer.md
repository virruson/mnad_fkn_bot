# Задача 9. Сердечки: счётчик и пасхалки

Промт для разработчика. Дизайнер не нужен: тексты и эмодзи даны ниже. Задача дополняет задачу 6 («Обратная связь») и меняет её правило «спасибо можно сказать один раз».

## Что сейчас в коде (сверено)

- `users.thanked_at` — время первого «спасибо». Повторное нажатие ничего не меняет и показывает `THANKS_AGAIN = "Ваше спасибо уже засчитано"`.
- Кнопка: `thanks_label(thanked, total)` → `🤍 Спасибо · N` / `❤️ Спасибо · N`. Здесь N — число **студентов**, сказавших спасибо (`count(thanked_at IS NOT NULL)`).
- Автору при первом «спасибо» уходит тихое сообщение `❤️ Спасибо · Имя · всего N` (`thanks_message`).
- Экран перерисовывается через `show_screen` (edit), подсказка показывается через `query.answer(toast)`.

## Что нужно

Сердечки можно жать много раз, каждое нажатие считается. На круглых числах студента ждёт маленький сюрприз.

## 1. Данные (миграция)

- `users.thanks_count INT NOT NULL DEFAULT 0` — сколько раз студент нажал сердечко.
- Заполнение при миграции: `thanks_count = 1`, если `thanked_at IS NOT NULL`, иначе 0.
- `thanked_at` оставить: это время первого нажатия, автору пригодится.

## 2. Кнопка

- Подпись `🤍 Спасибо` или `❤️ Спасибо · N`, где **N — сумма `thanks_count` по всем студентам**, то есть всего сердечек. Значок, как и раньше: `🤍`, если сам студент ещё не нажимал, `❤️`, если уже нажимал.
- `thanks_label` принимает `(my_count, total)`. `THANKS_AGAIN` больше не используется, удалить.

## 3. Что происходит при нажатии

Каждое нажатие: `thanks_count += 1` (атомарно, `UPDATE … SET thanks_count = thanks_count + 1 RETURNING thanks_count`), затем по новому значению `n`:

| n | Что видит студент |
|---|---|
| 1 | подсказка `Спасибо дошло до автора ❤️` |
| 2–4, 6–9, 11–14, … (не кратно 5) | подсказка `❤️ ×n` |
| 5 | подсказка `И тебе спасибо 😊` |
| 10, 15, 20, … (кратно 5, начиная с 10) | подсказка `❤️ ×n` **и** отдельное сообщение из одного эмодзи (п. 4), которое исчезает через 4 секунды |

- Подсказка (`query.answer(text)`) в Telegram сама исчезает через пару секунд. Это и есть «исчезающее сообщение» для 5, ничего дополнительно делать не нужно.
- Тексты вынести в `services/feedback.py` рядом с остальными.

## 4. Пасхалки на 10, 15, 20 …

- Бот отправляет **одно эмодзи без текста**. Такое сообщение Telegram показывает крупным, а многие эмодзи ещё и анимирует.
- Порядок:

  | n | эмодзи |
  |---|---|
  | 10 | 🤩 |
  | 15 | 😍 |
  | 20 | 🥰 |
  | 25 | 💖 |
  | 30 | 😻 |
  | 35 | 🫶 |
  | 40 | 💞 |
  | 45 | 🎉 |
  | 50 | 🏆 |
  | 55 и дальше | по кругу с 😍 (15, 20, … 50) |

  Хранить списком `CELEBRATION = ["🤩", "😍", "🥰", "💖", "😻", "🫶", "💞", "🎉", "🏆"]`, индекс `(n // 5 - 2)`; после конца списка — по кругу без первого элемента.
- Сообщение отправляется с `disable_notification=True` и через `context.job_queue.run_once(..., when=4)` удаляется (`delete_message`). Ошибку удаления (уже удалено, старое) игнорировать.
- Это сообщение **не экран**: в `SCREEN_MSG_KEY` его не записывать, экран «Обратная связь» остаётся на месте.
- Если в `python-telegram-bot` доступен параметр `message_effect_id`, на 50 можно добавить эффект 🎉. Это необязательно: если версия библиотеки не поддерживает параметр, не обновлять её ради этого.

## 5. Автору — без спама

- Сообщение автору (тихое) уходит, только когда студент нажал в первый раз (`n = 1`, как сейчас) и на `n` = 10, 25, 50, 100:
  ```
  ❤️ Спасибо · Анна Смирнова (@anna_smr) · всего 312
  ❤️ ×25 · Анна Смирнова (@anna_smr) · всего 312
  ```
  `всего` — сумма сердечек по всем студентам. На остальные нажатия автору ничего не приходит.

## 6. Частые нажатия

- Каждое нажатие считается, ограничения на количество нет.
- Перерисовка экрана (edit) нужна только ради числа на кнопке. Если с прошлой перерисовки у этого студента прошло меньше 1 секунды (`context.user_data['thanks_last_render']`), экран не перерисовывать, только `query.answer`. Иначе на быстрых нажатиях Telegram вернёт 429.
- `RetryAfter` и `BadRequest: message is not modified` при перерисовке ловить и игнорировать.

## 7. Макет

В `docs/ui_feedback.md` §2:
- число на кнопке теперь означает «всего сердечек»;
- строку про повторное нажатие заменить таблицей из п. 3;
- в легенду добавить эмодзи из п. 4.

## Критерии готовности

- Пять нажатий подряд: 1-е — «Спасибо дошло до автора ❤️», 2–4 — «❤️ ×2…4», 5-е — «И тебе спасибо 😊». Число на кнопке растёт.
- 10-е нажатие: появляется крупное 🤩 и через ~4 секунды исчезает, экран остаётся на месте.
- 15-е — 😍, 20-е — 🥰. На 55-м снова 😍.
- Автору приходят только 1-е, 10-е, 25-е, 50-е и 100-е, все без звука.
- 20 быстрых нажатий подряд: бот не падает, счётчик = 20, в логах нет необработанных 429.
- После миграции у тех, кто уже говорил спасибо, счётчик равен 1, и число на кнопке не уменьшилось.
